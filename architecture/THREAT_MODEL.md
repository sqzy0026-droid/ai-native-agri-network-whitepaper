# 威胁模型

## 1. 保护目标

- 农户身份、商品、订单和凭证可以迁移；
- 消费者隐私不因“开放”而被公开；
- AI不能绕过人工授权形成重大承诺；
- 村级节点不能单独篡改历史或永久封禁农户；
- 索引不能暗中把付费变成自然排序；
- 插件不能借工具权限窃取数据或修改交易。

## 2. 主要威胁与控制

| 威胁 | 可能后果 | 首版控制 |
|---|---|---|
| 村级操作员偏袒 | 商品准入和售后不公 | 关键操作双人复核、农户可见日志、申诉 |
| 虚假批次证据 | 消费者受骗、食品风险 | 多方证据、抽检、证据撤销状态、责任分离 |
| 索引排序捕获 | 形成新流量垄断 | 推荐凭证、多索引查询、公开快照、广告分离 |
| 模型幻觉 | 编造品质或库存 | 所有确定性陈述引用协议对象；状态机复核 |
| 提示注入 | AI调用越权工具 | 工具级权限、输入隔离、外部内容不产生授权 |
| 插件供应链攻击 | 数据泄露、宿主被控制 | 插件来源清单、签名、最小权限、进程隔离 |
| 支付回调伪造 | 虚假付款或退款 | 持牌机构签名回调、幂等键、服务端复核 |
| 事件重放 | 重复下单或重复退款 | 全局事件ID、幂等键、序列和时间窗口 |
| 数据导出泄露隐私 | 消费者信息扩散 | 分类导出、消费者授权、脱敏、审计 |
| 单一模型或托管商停服 | 网络大面积不可用 | 模型适配器、离线队列、数据快照和恢复演练 |

## 3. 不能由技术单独解决的问题

- 现场核验人员故意作假；
- 检测样品与实际发货批次不一致；
- 农户、村级节点、物流和消费者之间的责任争议；
- 公开数据导致大采购方更精准地压价；
- 节点劳动投入长期得不到合理报酬。

这些问题必须通过抽检、责任合同、保险、申诉、公开统计和经济激励共同处理。

## 4. 强制失败演练

每次试点扩张前至少执行：

1. 关闭默认索引，验证另一个索引能继续发现商品；
2. 更换模型，验证未完成会话可以恢复；
3. 模拟村级操作员离任，完成密钥轮换和数据交接；
4. 提交恶意提示，验证AI不能越权退款或改收款账户；
5. 注入重复支付回调，验证只产生一次支付事件；
6. 导出村级节点并在空环境恢复；
7. 对推荐结果重新计算，验证推荐凭证可复现。
